# Хореография объёмного текста: слои, таймлайны, физика, игровые моменты

Контекст: в движке уже есть пресеты (появление / жизнь / акцент / смена текста / уход) — функции времени, отдающие трансформ каждой буквы. Задача заметок — как запускать несколько одновременно и собирать сцены. Всё, что помечено «вывод», — моя рекомендация/расчёт, а не цитата источника.

## 1. Слои и сложение анимаций (Unity, Unreal, Spine, Rive, Motion/GSAP)

### Takeaway
Во всех зрелых системах одна и та же модель: стопка слоёв снизу вверх, каждый слой либо **заменяет** (override, с весом alpha = lerp к своему значению), либо **добавляет** дельту к результату нижних (additive, тоже с весом); смена состояния внутри слоя — кроссфейд с длительностью mix. Для нашего движка: база (появление/жизнь) — override, акценты/тряска/физика — additive-дельты; смещения складываются, масштабы перемножаются, повороты складываются (малые углы) или перемножаются кватернионами, прозрачность перемножается.

### Cited Findings
- Unity: Override «использует анимацию этого слоя, заменяя анимацию предыдущих слоёв»; Additive «добавляет анимацию слоя поверх предыдущих». Слои вычисляются по возрастанию индекса, каждый смешивается с результатом слоёв ниже — [Unity Manual 2022.3, Animation Layers](https://docs.unity3d.com/2022.3/Documentation/Manual/AnimationLayers.html)
- Unity: для успешного additive анимация на аддитивном слое должна содержать те же свойства, что и предыдущие слои; маска (Avatar Mask) ограничивает слой частью тела (бросок только верхом туловища при беге) — [Unity Manual](https://docs.unity3d.com/2022.3/Documentation/Manual/AnimationLayers.html); enum `AnimatorLayerBlendingMode`: Override / Additive — [Unity ScriptReference](https://docs.unity3d.com/es/ScriptReference/Animations.AnimatorLayerBlendingMode.html)
- Unreal: узлы Apply Additive и Apply Mesh Space Additive добавляют аддитивную позу к базовой с коэффициентом alpha (0 — базовая поза, 1 — полная добавка); Blend Bone by Channel — выбор отдельных костей — [Epic, Animation Blueprint Blend Nodes](https://dev.epicgames.com/documentation/en-us/unreal-engine/animation-blueprint-blend-nodes-in-unreal-engine)
- Unreal Layered Blend Per Bone: вес по костям через branch filters или blend mask; `bMeshSpaceRotationBlend` — смешивать поворот в пространстве меша или в локальном — [UE API FAnimNode_LayeredBoneBlend](https://docs.unrealengine.com/4.26/API/Runtime/AnimGraphRuntime/AnimNodes/FAnimNode_LayeredBoneBlend/index.html)
- Unreal (пользовательский отчёт UE 4.8): аддитив + per-bone blend наклонял корпус при смене нижней анимации; пропало, когда опорная поза аддитива совпала с её первым кадром — т.е. аддитив = (кадр − опорная поза), опора должна быть «нулём» — [UE AnswerHub](https://answers.unrealengine.com/questions/325874/view.html) (не официальная рекомендация)
- Spine: треки нумеруются с 0, применяются по порядку снизу вверх, верхние перекрывают нижние в том, что они ключуют; `TrackEntry.alpha` < 1 смешивает трек с нижними (пример: «хромота» растёт с уроном) — [Spine: Applying Animations](https://eu.esotericsoftware.com/spine-applying-animations)
- Spine: кроссфейд при смене анимации на треке — `AnimationStateData.setDefaultMix(0.1)` (в примере), `setMix(from, to, duration)` для пары, `TrackEntry.mixDuration` (пример 0.6 с) для одной записи; `setAnimation` заменяет текущую и очередь, `addAnimation(track, name, loop, delay)` ставит в очередь — [Spine: Applying Animations](https://eu.esotericsoftware.com/spine-applying-animations)
- Spine: «пустая анимация» нужна, чтобы плавно войти/выйти из позы покоя: `setEmptyAnimation` → `addAnimation` с mixDuration 1.5; выход — `addEmptyAnimation(track, 1.5, 0)`; без неё трек при `trackEnd` мгновенно сбрасывает свойства в setup pose (рывок) — [Spine: Applying Animations](https://eu.esotericsoftware.com/spine-applying-animations)
- Spine additive: значения аддитивных таймлайнов прибавляются к setup/current pose вместо замены — [TrackEntry API (spine_flutter)](https://pub.dev/documentation/spine_flutter/4.3.6/generated_track_entry/TrackEntry-class.html); на форуме: аддитив без ключей на нижних треках копился кадр за кадром — отдача превратилась во вращение; нужен базовый ключ на нижнем треке и пустая анимация для выхода — [Spine forum, MixBlend_Add](https://fr.esotericsoftware.com/forum/d/17207-trouble-animating-with-tracks-and-mixblend_add); mixDuration 0 = мгновенная смена без смешивания — [Spine forum](https://esotericsoftware.com/forum/d/10550)
- Rive: типы состояния — одиночная анимация, 1D blend, Additive blend; Additive Blend смешивает несколько таймлайнов, каждый со своим числовым параметром (позы, мимика) — [Rive docs: States](https://rive.app/community/doc/states/docEwEIEWU1U); переходы: длительность, Exit Time (время или %), «Pause when exiting» — [Rive docs: Transitions](https://rive.app/docs/editor/state-machine/transitions)
- Motion (бывш. Framer Motion) spring: страница (в извлечении) даёт stiffness 1, damping 10, mass 1, bounce 0.25, duration 800 мс, restDelta 0.01, restSpeed 0.1; `velocity` по умолчанию = **текущая скорость значения** — т.е. прерванная пружина стартует с текущей скорости — [motion.dev/docs/spring](https://motion.dev/docs/spring) (примечание: значение stiffness 1 выглядит странно, возможно извлечено неточно — проверить)
- Пружины сохраняют текущую скорость и перенаправляются плавно, CSS keyframes нельзя перенаправить — только перезапуск с начальных значений; проверка: запустить и развернуть посреди — элемент должен продолжить с текущей скоростью — [emilkowalski/skills (вторичный)](https://instagit.com/emilkowalski/skills/when-to-use-spring-animations-vs-css-transitions.md)

### Inferences
- **Правила сложения для нашего per-letter трансформа** (вывод, стандартная практика аддитивного блендинга): у каждого слоя на букву выдаётся `{dx,dy,dz, rx,ry,rz, sx,sy,sz, a}`.
  - смещение: `p = Σ wᵢ·dᵢ` (additive) или `p = lerp(p, dᵢ, wᵢ)` (override);
  - масштаб: `s = Π (1 + wᵢ·(sᵢ−1))` — умножение с весом через «1+доля», иначе вес 0 даст масштаб 0;
  - поворот: для углов < ~30° достаточно суммы Эйлеров `r = Σ wᵢ·rᵢ`; для переворотов (флипы букв у нас есть) — кватернионы: `q = q · slerp(I, qᵢ, wᵢ)`;
  - прозрачность: `a = Π (1 − wᵢ·(1−aᵢ))`; уход и появление перемножаются — тогда «акцент во время ухода» не вернёт непрозрачность;
  - цвет/свечение: max или аддитивно с клампом.
- **Опорная поза = ноль.** Каждый аддитивный пресет обязан возвращать ровно нулевую дельту (масштаб 1, альфа 1) в начале и в конце — иначе повторится баг Unreal/Spine (накопление/перекос). Это стоит проверять автотестом: `f(0)` и `f(end)` == identity.
- **Минимальная стопка слоёв** (вывод): L0 `base` (override: appear → idle → exit, кроссфейд внутри), L1 `accent` (additive, одноразовые пульсы: punch/shake/wave, можно несколько одновременно — суммируются), L2 `physics` (additive: пружины, отскок, магнит), L3 `camera` (трансформ всей надписи: zoom-punch, тряска, наклон). Маска = массив весов по буквам (аналог Avatar Mask / per-bone blend): «трясти только цифру, которая сменилась», «волна по диапазону i..j».
- **Длительности кроссфейда** (вывод из примеров Spine 0.1–0.6 с и UI-практики): idle↔accent 80–150 мс, appear→idle 150–250 мс (чтобы не было «щелчка» на стыке), смена текста 200–300 мс, idle→exit 0 мс (уход сам стартует из текущей позы). mix = 0 — только для намеренно жёстких ударов (slam).
- **Прерывание**: при смене состояния не сбрасывать в позу пресета, а брать текущее значение и скорость (запоминать pose(t) и pose(t−dt)) и вести к цели пружиной — как в Motion, где `velocity` по умолчанию = текущая скорость. Для тайм-функций без состояния — кроссфейд «от снимка позы» (freeze-frame последней позы + mix), как Spine `mixingFrom`.

### Gaps
- Не нашёл официального описания поведения Spine при прерывании посреди mix (цепочка mixingFrom, holdPrevious) — на странице «Applying Animations» нет.
- Lottie: не исследовал — Lottie не имеет рантайм-слоёв/смешивания (только проигрывание сегментов), подтверждающего источника не собрано.
- GSAP overwrite/`quickTo` и сложение твинов на одном свойстве — не проверено в этом проходе.
- Значение stiffness по умолчанию у Motion (1) вызывает сомнение — WebFetch мог извлечь неточно.

## 2. Таймлайн / секвенсор: минимальный API

### Takeaway
Почти все сцены покрываются GSAP-подобным таймлайном: «добавь клип в позицию» с позициями абсолютное время / метка / «<» (одновременно с предыдущим) / «>» (после предыдущего) / ±смещение / % длительности, плюс stagger по буквам и вложенные таймлайны. Плюс два AE-примитива: `valueAtTime` (задержка-эхо) и затухающая синусоида inertial bounce.

### Cited Findings
- GSAP position parameter: число = абсолютное время; `"label"` (если нет — создаётся в конце); `"<"` — начало предыдущей анимации; `">"` — конец предыдущей; `"+=X"` — пауза X после конца таймлайна; `"-=X"` — перекрытие X с концом; `"label+=X"`; `"<0.2"` = `"<+=0.2"`; `">-0.5"`; `"-=25%"` — перекрытие на 25% длительности вставляемой анимации; `"<25%"` — 25% внутрь предыдущей (= `">-75%"`); проценты с GSAP 3.7.0; «предыдущая» = последняя добавленная, не обязательно ближайшая к концу; по умолчанию `"+=0"` — цепочка идёт встык — [GSAP: Position Parameter](https://gsap.com/resources/position-parameter/)
- `addLabel(name, ">")` ставит метку в конец предыдущей анимации; по умолчанию `"+=0"` (конец таймлайна) — [GSAP addLabel()](https://gsap.com/docs/v3/GSAP/Timeline/addLabel())
- AE inertial bounce (Dan Ebberts): затухающая синусоида после ключа, амплитуда от скорости на ключе; старые параметры amp 5, freq 1.0, decay 5.0 давали переполнение `Math.exp(decay*t)` примерно на t≈142 с, исправление — считать только `t < 10`; поздняя версия amp 0.05, freq 4.0, decay 8.0, ограничение `t < 1` — «этого хватает, чтобы затухание закончилось» — [Adobe Community, inertial bounce](https://community.adobe.com/t5/after-effects-discussions/error-in-line-11-ae-inertial-bounce-created-by-dan-ebberts-at-motionscript-com/m-p/9289049)
- Ebberts: разные amp/freq/decay на каждую пару ключей — массивы и индекс n−1 — [Adobe Community 2023](https://community.adobe.com/t5/after-effects-discussions/inertial-bounce-multiple-times-on-the-same-property/m-p/13578026); сдвиг по времени: заменить `time` на смещённую переменную и `value` на `valueAtTime` — [Adobe Community 2018](https://community.adobe.com/t5/after-effects/offset-in-time-and-inertial-bounce-expressions-together/m-p/9784480)

### Inferences
- **Минимальный API (вывод)**, покрывает ~90% сцен:
  ```js
  const tl = T.timeline({ defaults:{ ease:'out3' } })
    .add('drop',   { stagger: 0.04, from:'center' })  // встык (">")
    .add('shake',  { amp: 6 }, '<0.25')               // через 0.25 с после старта drop
    .label('hit')                                     // момент удара
    .call(() => sfx('boom'), 'hit')                   // звук/вибро на метке
    .add('glow',   {}, 'hit-=0.05')                   // упреждение
    .add('idle',   { loop:true }, '>');
  tl.play(); tl.timeScale(1.5); tl.seek('hit'); tl.reverse();
  ```
  Обязательные: `add(clip, opts, pos)`, `label`, `call`, `stagger {each|amount, from: start|center|end|edges|random(seed), ease}`, вложенность (таймлайн как клип), `timeScale`, `seek`, `onComplete`. Позиции — ровно GSAP-набор выше (без %, если экономить). Клип = пара (слой, пресет) из раздела 1, т.е. «add» = поставить запись на трек с весом и mix.
- **Inertial bounce как универсальный «доводчик»** (вывод, формула Ebberts): `offset = v · amp · sin(2π·freq·t) / exp(decay·t)`, `v` — скорость в момент прихода. Стартовые значения для букв: freq 3–4 Гц, decay 6–8, считать только t < 1 с (Ebberts). Это дешевле пружины и детерминировано.
- **valueAtTime → эхо/шлейф**: буква i берёт позу ведущей буквы в момент `t − i·lag` (lag 30–60 мс) — даёт «змейку» и хвост без отдельного пресета.
- **Детерминизм**: все `random` в stagger — от сида (seed надписи), чтобы повтор и съёмка `fx-shots` давали тот же кадр.

### Gaps
- anime.js (v4 timeline, `'<<'`/`'+=100'` синтаксис) и Theatre.js не проверены в этом проходе — подтверждённых цитат нет.
- `wiggle(freq, amp)` AE — параметры из памяти, без источника здесь.

## 3. Физика для букв: тела, пружины, верёвки, магнит, гравитация

### Takeaway
Для 5–20 букв полноценный движок (Matter.js/Box2D) избыточен: достаточно per-letter пружины (полуявный Эйлер или аналитическая) + плоскость пола с коэффициентом отскока + трение; верёвки — Verlet с 2–4 итерациями ограничений. Детерминизм — фиксированный шаг (1/60 или 1/120) с аккумулятором и сидом.

### Cited Findings
- Matter.js значения по умолчанию: `friction` 0.1, `frictionAir` 0.01 (0 = нет сопротивления воздуха), `frictionStatic` 0.5; трение пары = `Math.min(bodyA.friction, bodyB.friction)` — [Phaser matter.d.ts (типы Matter)](https://cdn.jsdelivr.net/npm/phaser@4.1.0/types/matter.d.ts); [Phaser MatterBodyConfig](https://app.unpkg.com/phaser@4.2.1/files/src/physics/matter-js/typedefs/MatterBodyConfig.js)
- Matter.js `restitution` по умолчанию 0; 1 = сохраняется вся кинетическая энергия после удара — [Tuts+: Matter.js Body module](https://code.tutsplus.com/getting-started-with-matterjs-body-module--cms-28835t) (один источник)
- Пружины сохраняют скорость при перенаправлении; motion.dev: bounce 0.25 по умолчанию, restDelta 0.01, restSpeed 0.1 — критерии остановки — [motion.dev/docs/spring](https://motion.dev/docs/spring)
- Nuclear Throne (Vlambeer), один выстрел: камера отбрасывается на 6 px от точки прицела, screenshake += 4 и быстро затухает, отдача оружия = 2 (спрайт отъезжает и возвращается) — [infovore.org, пересказ интервью RPS](https://infovore.org/?p=5275)

### Inferences
- **Пружина на букву (вывод, стандартная формула)**: `a = −k(x−x₀) − c·v`; для «упругого UI» ζ (damping ratio) 0.4–0.6 при f 3–5 Гц: `k = (2πf)²`, `c = 2ζ·2πf` (масса 1). Примеры: «желе» f 4 Гц ζ 0.35; «твёрдо, без колебаний» f 6 Гц ζ 1.0. Шаг — полуявный Эйлер на фиксированном dt = 1/120 (2 подшага на кадр 60 fps) — стабильно при f ≤ ~15 Гц.
- **Падение с отскоком** (вывод): g ≈ 2500–4000 px/с² в масштабе экрана телефона (настоящие 9.8 м/с² выглядят вяло для текста высотой ~60 px); restitution 0.35–0.5 для «тяжёлого металла», 0.6–0.7 для «резины»; гасить скачки, когда |v| < 40 px/с; трение по полу (горизонталь) — множитель 0.8 за удар; задержка падения букв 40–60 мс stagger. Число видимых отскоков ≈ log(v_min/v₀)/log(e): при e = 0.45 — 2–3 отскока — то, что нужно.
- **Верёвка/«висящая буква»** (вывод): Verlet: `x_new = x + (x − x_prev)·(1−drag) + a·dt²`, drag 0.02, 3–6 точек на «нитку», 3 итерации ограничения длины; буква — последний узел, её поворот = угол последнего сегмента. Один раз сломать нитку (буква падает) — сильный «уход».
- **Магнит/отталкивание от пальца** (вывод): сила `F = s · (1 − d/R)²`, R ≈ 1.5–2 высоты буквы, ограничить смещение 0.5 высоты; возврат — та же пружина (f 3 Гц, ζ 0.5). Ветер — общий шум 0.3–0.6 Гц × фаза по индексу буквы (не рандом каждого кадра).
- **Буквы как твёрдые тела** (Matter.js/Box2D-демо) оправданы только для «осыпать надпись в кучу» — и то лучше заранее посчитать (запечь) траектории офлайн с фиксированным сидом и проиграть как ключи: детерминизм и ноль стоимости на телефоне.
- **Детерминизм и дешевизна**: фиксированный dt + аккумулятор; никаких `Math.random` в шаге (только сид); физика как additive-слой L2 (раздел 1) — когда все буквы в покое (|v|<restSpeed и |x−x₀|<restDelta, как у Motion) — слой выключается и не будит кадр (соответствует правилу проекта «цикл не будит страницу»). Расчёт — на JS (до ~30 тел это микросекунды), в шейдер уходит только итоговый трансформ.

### Gaps
- Не нашёл первоисточник Matter.js docs (значения взяты из типизаций Phaser); restitution 0 — один источник.
- Подтверждённых чисел из конкретных «физических» текстовых демо (Matter.js text demos) не собрано.

## 4. Рецепты игровых моментов с таймингами

### Takeaway
Публичных покадровых таймингов анонсеров (SF/Tekken «ROUND 1 — FIGHT»), Clash Royale/Brawl Stars и слотов почти нет — точные цифры ниже в основном мои выводы, опирающиеся на подтверждённые общие правила: хитстоп 50–100 мс на сильный удар (2–4 кадра лёгкий, 6–10 тяжёлый при 60 fps), тряска от «травмы» в квадрате, эскалация выигрыша ступенями-порогами.

### Cited Findings
- Хитстоп (стоп-кадр в момент удара): 50–100 мс на тяжёлый удар — [Wayline: Game Feel & Juice](https://www.wayline.io/learn/game-feel/1); «0.05–0.1 с работает лучше всего: короче — незаметно, длиннее — кажется лагом» — [eastondev blog, 2026](https://eastondev.com/blog/en/posts/dev/20260521-game-feedback-feel/)
- По кадрам при 60 fps: 2–4 кадра полной остановки для лёгкого, 6–10 для тяжёлого — [gamineai, 2026](https://gamineai.com/blog/pixel-art-combat-fx-hitstop-smear-frames-impact-timing-2026); KOF XIII: 7 кадров для лёгких, 11 для тяжёлых — [SuperCombo Wiki KOF XIII](https://srk.shib.live/w/The_King_of_Fighters_XIII/Character_States/Hitstun_Blockstun_state); SF6: у более тяжёлых атак хитстоп длиннее (без чисел) — [SuperCombo SF6 Game Data](https://srk.shib.live/w/Street_Fighter_6/Game_Data)
- Хитстоп замораживать только участников, не UI/звук/эффекты; считать в unscaled time — [bugnet.io](https://bugnet.io/blog/how-to-fix-hitstop-or-freeze-frame-feeling-off); hit stop — одна из трёх функций, сильнее всего влияющих на ощущение удара (вместе со связностью звука и управлением камерой) — [SciTePress 2024](https://www.scitepress.org/Papers/2024/124614/124614.pdf)
- Ступени выигрыша в слоте (пример мобильного слота): Big Win ≥ 500 монет, Mega ≥ 5 000, Extra ≥ 50 000 (×10 на ступень), верхние ступени игроки видят редко — [TrueAchievements, Free Slots Fun Factory](https://www.trueachievements.com/forum/viewthread.aspx?tid=775484) (форум игроков; таймингов нет)

### Inferences
Все тайминги ниже — **вывод** (собраны из общих правил выше и отраслевой практики; источников с покадровыми данными не нашёл). Единицы — мс от старта; «удар» = посадка буквы + звук + вибро (`impactOccurred`).

- **Комбо / серия ×2, ×3…** (счётчик меняется на месте): 0 — старая цифра уходит вверх 90 мс (out); 60 — новая падает сверху `slam` 120 мс, ease-in; 180 — удар: punch-масштаб 1.0→1.35→1.0 за 160 мс (overshoot), тряска amp = 2 px × уровень; цвет теплеет на ступень; на ×5, ×10 — +хитстоп 60 мс перед ударом и zoom-punch камеры 1.06. Повторный триггер во время анимации — не перезапуск, а аддитивный пульс поверх (слой L1) + мгновенная смена цифры (t.count уже умеет). Вибро: light → medium с ×3 → heavy с ×5.
- **Level up**: 0–150 вспышка/затемнение фона (opacity 0→0.6); 150 — «LEVEL UP» `pop` stagger 35 мс от центра (≈ 8 букв → 245 мс); 450 — пауза-держание 250 мс; 700 — номер уровня `slam` + хитстоп 80 мс + heavy; 900–1600 idle-волна (амплитуда 4 px, 1.2 Гц); 1800 — уход вверх 250 мс. Итог ~2 с — длиннее отвлекает от игры.
- **Отсчёт 3-2-1-GO**: каждая цифра ровно 1000 мс (бит = 60 BPM, легко синхронизировать): 0–120 влёт с масштаба 2.0→1.0 + альфа 0→1; 120 удар (medium); 120–700 держание с лёгким дыханием (scale 1→0.96); 700–1000 уход: scale 1→0.6, альфа→0. «GO!» — длиннее и громче: влёт 100 мс, overshoot 1.0→1.25→1.0 за 200 мс, heavy + тряска камеры, уход в 500–700 мс разлётом букв (физика наружу). Цвет 3-2-1 — нейтральный, GO — акцентный.
- **«НОВЫЙ РЕКОРД»**: 0 — затемнение и letterbox 200 мс; 200 — слово «НОВЫЙ» `drop` stagger 40 мс; 450 — «РЕКОРД» `slam` всем словом (один удар — читается сильнее, чем побуквенно) + хитстоп 70 мс + zoom-punch 1.08 → 1.0 за 300 мс; 800 — число рекорда счётчиком (t.count) 600–900 мс с тиками на каждую смену цифры (selectionChanged не чаще ~25 Гц); финальный удар (success). Держать 1.2 с.
- **Эскалация выигрыша (Мега → Ультра → Джекпот)**: порог-ступени по множителю (у нас ранги). Каждая ступень = свой «удар» и смена надписи (смена текста-пресет 250 мс): Мега — прокрутка счётчика 1.2 с, один удар; Ультра — 1.8 с, на переходе через порог — хитстоп 80 мс + смена слова + тряска уровня 2; Джекпот — 2.5–3 с, два порога, финал с zoom-punch 1.12, Dutch-tilt 4–6° на 400 мс, heavy ×2 с интервалом 120 мс. Тап — пропуск к финальному кадру (seek в конец, удар без промежуточных). Честность: эскалация показывает только уже определённый исход, ступень меняется по реальному счётчику — не «почти джекпот».
- **Предупреждение таймера (последние 5 с)**: каждую секунду на её смене: punch 1.0→1.18→1.0 за 180 мс, цвет к красному линейно 5→1; с 3 с — + тряска 1.5 px и тик-вибро light; последняя секунда — двойной пульс (0 и 500 мс). Ничего не прыгает по раскладке: только transform. Связка с ареной: «за 5 с до старта тикеты зафиксированы» — на 5 с замок + первый пульс.
- **FIGHT! / VICTORY / DEFEAT**: FIGHT — 0 удар молота (уже есть у Арены), 0–80 буквы влетают из глубины (z −600 → 0) все вместе, 80 — хитстоп 60 мс + heavy + тряска травмы 0.6; держать 400 мс; уход разлётом 200 мс (бой должен начинаться быстро, всего ≤ 700 мс). VICTORY — `drop` stagger 50 мс, отскоки e≈0.45, glow, success; держать до тапа. DEFEAT — без удара: медленное появление 400 мс, буквы чуть «оседают» (y +4 px, наклон до 3°, кривая in-out), десатурация, вибро только warning; никакой тряски — проигрыш не должен «бить».
- **Раскрытие награды**: держание-предвкушение (заряд) 400–800 мс с нарастающей дрожью (амплитуда растёт линейно, частота 8→14 Гц) → хитстоп 80 мс → раскрытие + удар → название награды `pop` stagger 30 мс → сумма счётчиком. Длительность заряда — одна для всех исходов (иначе длительность выдаёт исход и это нечестный саспенс).
- **Ошибка / недостаточно средств**: горизонтальная тряска надписи (вся метка, не по буквам): 4 полупериода затухающей синусоиды, 8 → 6 → 4 → 2 px, ~300–350 мс всего (≈ 12 Гц), без масштаба; цвет — короткая подсветка красным 150 мс; `notificationOccurred('error')` в момент начала. Повтор во время тряски — перезапуск с амплитудой не выше текущей (не накапливать).
- **Тряска камеры как «травма»** (Eiserloh, раздел 5): удары добавляют trauma (лёгкий 0.2, средний 0.4, тяжёлый 0.6–0.8), сила тряски = trauma², затухание trauma ~1.5–2/с.

### Gaps
- Не нашёл покадровых данных о «ROUND 1 / FIGHT» (SF, Tekken), Fortnite/Clash Royale/Brawl Stars баннерах и длительностях празднования в слотах — поиск дал только SEO-мусор. Все тайминги раздела помечены как вывод; стоит снять с видео (60 fps, покадрово) при необходимости.

## 5. Камера и постановка текста

### Takeaway
Камера — отдельный аддитивный слой над всей надписью: zoom-punch, тряска «травмой» (trauma², шум, а не рандом), отдача-«кик» в сторону удара, Dutch-tilt, letterbox и фейковая глубина резкости. Поворот всей надписи — для смены состояния/акцента целиком (читается как один объект); по буквам — для появления, ухода и «живости».

### Cited Findings
- Squirrel Eiserloh, «Math for Game Programmers: Juicing Your Cameras With Math» (GDC 2016): геймплей добавляет trauma 0..1, линейное затухание, видимая тряска = trauma в степени (обычно 2); смещения через шумовую функцию — плавно и непрерывно — [Bevy example: 2D screen shake](https://bevy.org/examples/camera/2d-screen-shake/); квадрат держит мелкие удары тонкими, крупные — сильными — [Godot asset Simple Camera Shake](https://godotengine.org/asset-library/asset/735); Perlin вместо случайных чисел — [Camera Shaker (itch)](https://lucasserrano.itch.io/camerashaker). Примечание: числа — из реализаций сообщества, не со слайдов доклада.
- Vlambeer/Nuclear Throne: на выстрел камера отбрасывается 6 px, screenshake +4 и быстро гаснет — [infovore.org](https://infovore.org/?p=5275)
- Управление камерой — одна из трёх функций, сильнее всего влияющих на ощущение удара — [SciTePress 2024](https://www.scitepress.org/Papers/2024/124614/124614.pdf)

### Inferences
- **Zoom-punch** (вывод): scale 1.0 → 1.06–1.12 за 50–70 мс (ease-out), назад за 200–300 мс (ease-out/пружина ζ 0.6). Чем реже момент — тем больше (комбо 1.04, рекорд 1.08, джекпот 1.12).
- **Dolly-in** (вывод): медленный наезд 1.0→1.05 за 1.5–3 с на держании — даёт напряжение во время прокрутки счётчика/заряда; при ударе — punch поверх (additive).
- **Dutch-tilt** (вывод): 3–6° на 300–500 мс, только на пике (джекпот, VICTORY); возврат пружиной. Больше 8° — нечитаемо на телефоне.
- **Тряска** (вывод, по Eiserloh): `shake = trauma²`; `offset = maxOffset·shake·noise(seed, t·freq)`, `angle = maxAngle·shake·noise(seed+1, t·freq)`; maxOffset 8–12 px, maxAngle 2–3°, freq 15–25 Гц для удара, 4–6 Гц для «гула»; trauma −1.5…2 в секунду. Шум — детерминированный (у нас уже есть запечённый шум в Горне).
- **Letterbox** (вывод): полосы 8–10% высоты экрана, въезд transform translateY 200–250 мс; только для 2–3 самых больших моментов (рекорд, джекпот, начало боя).
- **Фейковая глубина резкости** (вывод): не блюр (дорого на iPhone и запрещено правилами — фильтры), а: дальние буквы/фон — ниже альфа и масштаб, плюс заранее размытая копия (запечённая текстура) с crossfade по opacity.
- **Целиком vs по буквам** (вывод): целиком — 3D-поворот при смене смысла (флип таблички «Мега→Ультра»), отдача, наклон, тряска ошибки; по буквам — появление/уход, волна idle, акцент сменившейся цифры. Не смешивать оба на одном моменте сильнее одного-двух слоёв — иначе читается «каша».

### Gaps
- Доклад Eiserloh (оригинальные слайды и числа) не открыт — числа из вторичных реализаций.
- Нет источника по Dutch-tilt/letterbox в игровом UI с числами.

## 6. Синхронизация со звуком и вибрацией

### Takeaway
Звук и вибро должны совпадать с кадром посадки; человек терпимее к опозданию звука, чем к его опережению (окно заметности примерно +45 / −125 мс по ITU-R BT.1359, но знак спорен между источниками; строгие ATSC — не опережать больше 15 мс, не отставать больше 45 мс). Практически: удар звука = кадр контакта ±1 кадр, и строить таймлайн на метках, к которым привязаны и визуал, и `call(sfx)`, и haptics.

### Cited Findings
- ITU-R BT.1359: порог заметности от +45 мс до −125 мс, порог приемлемости от +90 до −190 мс (плюс — звук опережает видео); окно асимметрично — опоздание звука переносится лучше — [USPTO патент 10063907](https://image-ppubs.uspto.gov/dirsearch-public/print/downloadPdf/10063907); [TV Technology](https://www.tvtechnology.com/opinions/av-synchronization-how-bad-is-bad); NTIA приводит те же величины с обратным знаком — [NTIA report 11-474](https://its.ntia.gov/publications/download/11-474.pdf) (конфликт знаков)
- ATSC (строже для ТВ): звук не должен опережать видео больше 15 мс и отставать больше 45 мс — [TV Technology: Managing lip sync](https://www.tvtechnology.com/opinions/managing-lip-sync-265013)
- BT.1359 построен на роликах с диктором; для музыки (гитара, фортепиано) пороги выше — [arXiv 2212.01686](https://ar5iv.labs.arxiv.org/html/2212.01686)
- Telegram Mini App HapticFeedback (Bot API 6.1+): `impactOccurred(style)` — light, medium, heavy, rigid, soft; `notificationOccurred(type)` — error, success, warning; `selectionChanged()` — только при смене выбора, не при подтверждении — [Telegram Mini Apps docs](https://core.telegram.org/bots/webapps)
- Связность звука — одна из трёх функций ощущения удара — [SciTePress 2024](https://www.scitepress.org/Papers/2024/124614/124614.pdf)

### Inferences
- **Привязка** (вывод): в таймлайне каждая «посадка» — метка; на ней `call` звука (WebAudio, `ctx.currentTime + lookahead`) и haptics. Звук планировать на 0–15 мс раньше расчётного кадра контакта (компенсирует задержку вывода кадра ~1 кадр), не позже 45 мс (ATSC). Для синтезированного звука WebAudio это реально.
- **Хитстоп и звук**: звук стартует в начале хитстопа (кадр контакта), визуал «замирает», вибро — тоже в начале. Хвост звука = разрешение напряжения.
- **Стаггер по буквам и звук**: не звучать на каждую букву, если интервал < ~40–50 мс (сливается в шум и рвёт вибромотор) — объединять в один удар на первой/последней букве или «тики» с прореживанием до ≤ 20–25 Гц. Вибро — максимум 1 impact на ~60–80 мс (вывод; Taptic Engine всё равно сольёт чаще).
- **Бит**: для отсчёта и счётчиков выбирать шаг кратный биту (60 BPM = 1000 мс, 120 BPM = 500 мс, 150 BPM = 400 мс); stagger 1/8 или 1/16 бита (при 120 BPM — 62.5 / 31 мс). Ускорение саспенса — сокращение интервала тиков по кривой (например 200 → 60 мс), финальный удар — на сильную долю.
- **Шкала силы**: ступень момента → стиль вибро: тик — selectionChanged (только когда реально меняется значение), лёгкая посадка — light/soft, удар — medium/rigid, кульминация — heavy, итог — success/error/warning.

### Gaps
- Нет измерений задержки вибро/звука в Telegram WebView на iPhone и Android — стоит замерить самим (запись видео 240 fps).
- Не найдено исследований по допустимой рассинхронизации тактильного отклика и визуала (vision–haptics) с числами.
