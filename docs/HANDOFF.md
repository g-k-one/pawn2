# Как передать проект разработчику (или ИИ-агенту)

Памятка для владельца продукта. Код знать не нужно.

## Что передавать
Только ссылку на репозиторий GitHub: **g-k-one/pawn2**, ветка `main`. В репозитории всё нужное:
- `CLAUDE.md` — правила продукта и устройство кода. ИИ-агенты (Claude Code и подобные) читают его автоматически.
- `docs/BACKEND.md` — что сделать на сервере, какие данные нужны фронту, план переноса базы. Раздел 0 — что нового с прошлой передачи.
- `docs/MODES.md` — Арена и Ставки: правила, экраны, честность, API, риски, что сделать перед релизом.
- `docs/AI-DEV.md` — инструкция для ИИ-разработчика: откуда брать фронт, что менять, что обязан делать сервер, приёмка.
- `README.md` — как запустить и проверить.

## Как выдать доступ
1. GitHub → репозиторий → **Settings → Collaborators → Add people** → ник разработчика. Роль *Write*.
2. Если агент работает в облаке (Claude Code на claude.ai/code), достаточно подключить ему этот репозиторий.
3. Секреты (токен бота, ключи кошелька, доступ к базе) — **не** в чат и не в код. Только в настройках сервера/хостинга (переменные окружения) или GitHub → Settings → Secrets.

## Что написать разработчику (шаблон)
> Привет! Фронтенд Pawn готов как прототип: github.com/g-k-one/pawn2.
> Нужно подключить его к нашему бэкенду (pawn-backend) и перенести на него базу игроков.
> Всё описано в `CLAUDE.md` и `docs/BACKEND.md`: контракт API, схема данных, список заглушек, порядок работ.
> Главное: доказательства честности должны проходить https://pawn-frontend.onrender.com/verify/ — в репо есть тест на это (`npm test`).
> Интерфейс без согласования не менять; правки — отдельными pull request'ами, CI должен быть зелёным.

## Что попросить агента первым сообщением
> Прочитай docs/AI-DEV.md, потом CLAUDE.md и docs/BACKEND.md. Подключи фронт к бэкенду по плану из раздела «Порядок переноса», по одному шагу за pull request. После каждого шага — `npm run check` и скриншоты в headless Chromium.

## Как принимать работу
- На каждый pull request GitHub сам запускает проверку (галочка **check**). Красная — не мержить.
- Смотреть в Telegram на своём тестовом боте: крафт, кейс, депозит, вывод, проверка честности (кнопка «Проверить честность» → сайт проверки должен показать «проверено»).
- Сверить баланс игроков до и после переноса базы — суммы должны совпасть.

## Чего не делать
- Не править `index.html` в корне руками — он собирается из `src/`.
- Не выкладывать в прод с включённой дебаг-панелью (принудительный исход только для теста).
- Не отдавать server seed на фронт до раскрытия эпохи.
