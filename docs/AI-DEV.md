# Pawn: инструкция для ИИ-разработчика (подключение к бэкенду)

Прочитай этот файл целиком, потом `CLAUDE.md`, `docs/BACKEND.md` и `docs/MODES.md`. Работай по шагам ниже; после каждого шага выполняй `npm run check` и делай скриншоты в headless Chromium.

## 0. Откуда брать фронт
- Репозиторий **g-k-one/pawn2**, ветка **`main`**, последний коммит. Не бери старые копии, архивы и уже развёрнутые сборки: интерфейс сильно изменился.
- Как понять, что сборка актуальная:
  - в меню сверху карточка профиля и «Сезонный пасс», а не баннер «Бонусы»;
  - Арена — колизей с колесом тикета и кнопкой «меч и щит», а не ползунок «Тикет» с кнопкой «Войти»;
  - в «Ставках» у каждого исхода виден множитель («×2», «×4.5»), а не «×—».
- Сезонный пасс включён по умолчанию (`SEASON_ON`, флаг `bm-season`). Не выключай его.

## 1. Главное правило
**Фронт не переписывать.** Вся связь с сервером — только в `src/app/17-api.js` (объект `API`). Сейчас там мок. Замени его тела настоящими запросами, **сохранив имена методов, аргументы и форму ответов**: остальной код рассчитывает именно на них. Деньги и исходы игр — только через `API`. Интерфейс, тексты и анимации без согласования не менять.

Что реализовать (контракт и форма ответов — в `docs/BACKEND.md`):
- **Игра:** `craft`, `claimCraft`, `openCase`, `receipt`, `rotateSeed`, `bets`.
- **Арена:** `pvpOpen`, `pvpJoin`, `pvpChange`, `pvpState`.
- **Кошелёк:** `confirmDeposit`, `withdrawNft` (по одному подарку), `sellNfts`.
- **Сезон:** `seasonClaim`, `seasonBuy`, `seasonTask`, `cosEquip`.
- **Остальное:** `checkAch`, `claimRef`, `restoreDay`, `promo`, `shareCard`, `storyImage`, `storyReward`.
- **Списки:** `API.list(key)` — история, задания, друзья, топ. Если он падает, в списке видно «Не удалось загрузить».
- **Состояние игрока при запуске:** баланс, XP, инвентарь, nonce, эпоха, история, задания дня, сезон, оформление. Им заменяются заглушки — список заглушек в `docs/BACKEND.md`.
- Методы `dbg*` и `dbgSeason` — только для отладки, в бою не нужны: пусть возвращают `{ ok: false }`.

## 2. Сборка и выкладка
1. `npm install`, затем `npm run dist`. Получится папка `dist/`: собранный `index.html` и `assets/` со всеми подпапками, включая `assets/fx` с атласами эффектов.
2. Выкладывай **всю** `dist/`. Если картинок нет или путь к `assets` неверный, вместо щита и подарков будут белые пятна, а эффекты не появятся.
3. `index.html` в корне руками не править: он собирается из `src/`.

## 3. Что сервер обязан делать (иначе будут баги)
- **Честность `pawn-pf-v1`.** Хеш server seed — до игры, seed раскрывается при смене ключа. Доказательства должны проходить https://pawn-frontend.onrender.com/verify/ (`npm test` это проверяет). Server seed никогда не уходит на фронт до раскрытия.
- **Повторы.** У каждого денежного действия есть свой `rid`. Повтор с тем же `rid` отдаёт готовый ответ и не списывает деньги второй раз. Списание — условным UPDATE («списать, если хватает»).
- **Арена:**
  - время комнаты (кто вошёл, сколько осталось, когда разыгрывать) — по одним часам для всех экземпляров сервера;
  - бой разыгрывается с запасом ~1.5 с после таймера;
  - у игрока ровно один итог за комнату;
  - оформление соперников приходит в `entries[].eq`.
- **Задания дня засчитывает сервер.** Он сам считает счётчики и сам решает, сколько дать XP; XP с телефона не принимать.
- **Сезон:** награду за уровень можно забрать только один раз, только если уровень набран, а премиум-награду — только с купленным премиумом. Если сервер отказывает, в ответе должна быть понятная причина по-русски, например «Уровень ещё не набран».
- **Раздача подарков нескольким игрокам** (призы топа, NFT за сезон): у каждого свой экземпляр из стока релеера, с атомарным резервом.
- **Вывод** — только NFT, по одному, комиссия 0.3 GRAM (или бесплатный вывод из пасса).

## 4. Порядок работ
1. Развернуть актуальный `main` как есть, на моке, и убедиться, что он выглядит как прототип.
2. Состояние игрока при запуске: баланс, инвентарь, история, эпоха, nonce.
3. Крафт и забор выигрыша, затем проверка честности.
4. Кейсы, затем Ставки, затем Арена.
5. Кошелёк: депозит через TON Connect, поштучный вывод, продажа.
6. Сезон: задания, награды, премиум, оформление.
7. Лента «лайв», рефералка, промокоды, шеринг.

Каждый шаг — отдельный pull request с зелёной проверкой CI.

## 5. Приёмка (проверить в Telegram)
- Нет красных плашек «Не удалось загрузить», все картинки на месте.
- Крафт, кейс, Ставки, Арена: результат приходит с сервера, «Проверить честность» показывает «проверено».
- Баланс после действий совпадает с сервером, а после перезапуска приложения ничего не обнуляется: задания, сезон, оформление.
- На Арене места не мигают, кольцо таймера идёт плавно, бой стартует, когда кольцо дошло до конца.
- Пасс: «Забрать всё» забирает награды по очереди, при отказе показывает причину.
- Английский: `npm run i18n` показывает 0 ключей без перевода.

## Чего не делать
- Не менять интерфейс и не добавлять своих экранов или плашек без согласования.
- Не выкладывать в прод с дебаг-панелью (принудительный исход — только для теста).
- Не писать в лейблах «TON» — только GRAM.
- Не хранить токены и ключи в коде: только в переменных окружения сервера.
